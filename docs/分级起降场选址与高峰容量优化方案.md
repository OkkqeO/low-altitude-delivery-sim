# 分级起降场选址与高峰容量优化方案

编制日期：2026年10月18日。本文保留第一版开发前的扩展设计依据，其中“当前”指V0.5状态。预算、等级、联合选址与机队配比、正常/高峰冻结评价现已在V0.6实现；操作与实测结果见[分级起降场第一版](分级起降场第一版.md)。滚动调度仍为下一阶段，历史实验和参赛报告需按版本区分。

## 1. 借鉴依据与项目定位

已核对本地保存的2025年官方获奖名单第72页、第1678项：南京航空航天大学《分级垂直起降机场的选址问题》，数字建模智能决策赛道，一等奖。名单公告地址：https://www.siac.net.cn/article/10 。本地核对图为 `.verification/history-public-sources/award-pages/upright-72.png`。

目前没有该作品的正文、模型或代码，因此下文是结合本项目提出的设计，不能表述为复现、采用了该获奖作品的算法。与本项目相关的借鉴方向是设施分级、容量约束和网络配置。

本项目继续研究园区配送无人机起降场。建议扩展题目为“面向园区低空配送的分级起降场选址与容量配置仿真系统”。载人垂直起降机场的设施标准和运行模型需另行研究，当前模型不直接适用。

## 2. 当前高峰问题的证据

根据已保存的 `results/safety/runs/peak_*_staggered.json`，综合风险布局在5个种子的运行等权均值如下：

| 配送时间组成 | 秒/单 |
| --- | ---: |
| 等待无人机可用：ready-created_at | 655.17 |
| 原起飞位排队：prep_start-ready-airspace_delay | 22.65 |
| 本次任务额外错峰：airspace_delay | 12.42 |
| 起飞准备 | 25.00 |
| 去程飞行 | 42.94 |
| 配送处理 | 20.00 |
| 合计 | 778.18 |

等待无人机可用包含前序飞行、服务、排队和错峰的累积影响，不能全部归因为无人机数量不足。该组结果准时率均值为39.0%。

当前 `build_design()` 枚举两个场站，但 `simulate()` 固定按顺序分配无人机，5架通常为3+2；选址使用关闭错峰的设计订单。尚未显式评价场站等级、成本、可驻机数及其他机队配比。

## 3. 建议的最小版本

先保留两个场站、单站一个起降服务位和既有连续时间间距检测，扩展以下内容：

1. 候选站设置标准站、增强站等可选等级。等级定义建设成本、最大可驻机数，以及可选的起降服务时间；每项参数均需注明来源或演示假设。
2. 每个候选点记录允许的等级。适建性由人工核对的可用场地等资料给出，图片识别不自动认定场地适建。
3. 在总预算与总机队数量约束内，联合枚举两个站的位置、等级和无人机分配。5架无人机可比较1+4、2+3、3+2、4+1，过滤超过等级可驻机数的配置。
4. 对每种配置运行实际启用间距约束的调度，评价正常和高峰需求。优先使用现有调度形成新基线，之后加入滚动调度。

如果两种等级在成本、容量、服务时间和可行性约束上完全相同，等级不产生实际决策作用，应先补齐有解释的差异。站级名称本身不作为创新证据。

当前订单只有配送目的地，隐含每个站都能发出任意订单。最小版本沿用并明确此假设；若未来设置一个仓库中心与多个末端站，需要增加订单起点、库存或补货运输，并重新定义配送流程。

## 4. 决策变量与评价

设 x(i,k) 表示在候选点i选择等级k，n(i)为分配无人机数。最小版本约束：

- 每个候选点最多选择一个等级，共选择两个站；
- 建设成本之和不超过预算B；
- 无人机总数固定为D，且每个启用站至少一架；
- n(i)不超过所选等级的可驻机数；
- 满足候选点的等级允许条件、航路可达性、无人机任务不重叠、起降服务位预约及空中间距约束。

成本可先使用相对成本单位，明确属于演示设定，不包装为实际工程报价。各站服务时间需由调度器实际读取；若设置更快服务，应给出模型依据，并通过独立对照区分设施变化与调度算法贡献。

建议采用透明的分层评价：先最小化未完成订单，再最小化超时订单数，其次比较超时总时长、配送时间与路径暴露。在固定预算下选择方案，同时展示成本和不同目标间的取舍。人员暴露仍为代理指标。

正常与高峰场景的权重在设计前固定，也可采用两种场景中较差的准时率作为稳健性评价。布局、等级和机队分配均在设计阶段确定；独立评价阶段冻结配置，避免每个测试种子重新选址。

此方法属于使用运行仿真评价设施配置，可称为“仿真驱动的选址与容量配置优化”。只有枚举完给定有限候选集合且使用明确评分，才能称为该候选集合内评分最优；不声称城市规模或真实飞行全局最优。

## 5. 滚动调度作为第二阶段

按固定周期或无人机可用事件，对已到达、尚未开始执行的订单进行小批量匹配；评估预计送达、超时和后续无人机释放时间。已执行任务保留，尚未执行的预约可按明确冻结规则重排。

不得使用尚未到达的评价订单做实时调度决策。当前统一600秒时限下，单纯按最早截止时间排序与先来先服务基本等价；需要结合任务耗时、剩余裕量与等待时间，防止长任务被长期推迟。

## 6. 实施位置

| 文件 | 拟议改动 |
| --- | --- |
| engine.py / Config | 可选预算、设施配置策略与调度策略，默认保留现有行为 |
| engine.py / build_design | 枚举位置、等级、机队配比，调用实际调度评价设计场景 |
| engine.py / simulate | 接受显式无人机分配及站级服务参数，后续支持滚动调度 |
| map_import.py、map_document.py、map_editor.py | 场站允许等级、等级参数与来源编辑；兼容旧Excel和JSON默认值 |
| app.py、ui.py | 显示预算、等级、无人机配比及队列组成 |
| reporting.py、study.py | 导出设施配置、成本、超时与等待分解，保留原始配置和策略名称 |
| tests/ | 验证预算与容量约束、旧行为兼容、时序与间距约束、独立评价和结果可追溯 |

第一阶段无需增加三维画面。多起降位留待后续：需要独立服务日历、实际服务位位置及进离场约束，不能只把同一坐标的服务能力乘倍数就认为满足间距要求。

## 7. 对照实验

| 组别 | 改动 | 用途 |
| --- | --- | --- |
| A | 当前两站选址与默认3+2分配 | 保留已有基线 |
| B | 固定A的站点、站级和服务参数，仅优化无人机配比 | 隔离机队分配贡献 |
| C | 固定预算、机队总数及可用设施等级，优化选址、等级和配比 | 检验设施配置整体贡献 |
| D | 在C的条件下加入滚动调度 | 隔离调度改进贡献 |
| E | 改变预算、机队数或服务位数量 | 单独研究扩容效果 |

A至D采用同一套候选点、成本表及预算上限；既有场站补齐相应等级与成本，报告实际预算使用量。若新方案使用更高成本设施，应增加成本匹配对照，不能将设施投入增加计为纯算法收益。

使用同一批独立评价订单配对比较，报告准时率、失败数、平均及95分位配送时间、队列组成、路径暴露、间距事件、成本与计算耗时。设计与评价随机种子分离，评价时冻结选址与设施配置。

增加“固定网络从正常进入高峰”的检验，区别于现有每场景重新选址的实验。需求增长后可检验固定设施下的机队调配和滚动调度；站点增建属于另一项设施扩容决策。

## 8. 建议展示主线

“预算与候选场地给定时，场站的位置、等级和机队分配如何影响高峰配送？系统通过运行仿真比较可行配置，显示何时调整分配有效、何时需要增加设施投入。”

该扩展能形成具体、可检验的项目贡献。最终是否优于现有方案，必须以实现后的配对实验为准。
