## 根因与修改核对

评委先读实际`app.py`、`ui.py`、`map_editor.py`、`flight_map.py`及默认JSON，再用独立`-S`计算核对：默认场景960×640米、10栋建筑、8场站、10配送点。`create_scene → schematic_scene → result.scene → scene_data → MapEditor`没有换成另一张默认地图。旧主图却仅遍历`flight_obstacles`，45米巡航、5米垂直间距下只画B2/B3/B6/B9，遗漏B1/B4/B5/B7/B8/B10；编辑器始终画全部10栋。主要根因为绘制过滤，不是坐标数据错位。

|---|---|---|
|`ui.py:render_map`|改为遍历全部建筑；保留高度阈值，仅以深浅填色、轮廓和图例区分障碍状态；每栋有ID标签供核验|修复原4栋/10栋差异，不扩大实际避障对象|

评委读取历史冻结ZIP内相同源码并做归一化行尾差异比较。`engine.py`、`site_selection.py`、`facility.py`、`airspace.py`、`flight_map.py`、`decision_support.py`、`site_ui.py`及`data/demo_scene.json`与历史快照逐字节相同。没有发现本轮更改起飞点窗口布局或仿真/选址/调度规则。`reporting.py`的改变发生于SVG绘制，不能因此把当前文件称为历史协议的精确源码。

## 图层差异的验收解释

人员热点是同一份风险源数据，主图的高斯连续热力分布与编辑器用于调整中心/半径的椭圆承担不同用途；不要求二者画成同一种色块。默认通过显隐继承避免未主动打开的人群层突然出现。建筑名称同理。编辑器没有主图任务航路/动画，场站选中高亮与编辑选中高亮也不同，这些是已说明的操作视图差别，不代表换图。

当前结论针对默认矩形场景及脚本涵盖的Excel/现有图片/回放情形；不外推为任意新地图都已逐像素认证，也不声称原多边形的外接矩形近似已经消除。该保守近似与高度避障规则本轮均未改变。
