# 主地图与编辑地图一致性修复（2026-10-19）

本轮对应用户反馈：“一开始看到的地图在点击编辑地图之后会发现不一致”。仅处理地图展示及对应导出、说明和回归证据；起飞点优选仍在既有独立窗口。

## 根因及修复

默认模拟园区始终是960×640米、10栋建筑、8个候选场站、10个配送点。旧主图通过`flight_obstacles(scene)`筛选后绘制，45米巡航及5米垂直间距下仅显示B2、B3、B6、B9，共4栋；编辑器遍历全部建筑，所以额外显示6栋。计算结果交给编辑器的建筑数据相同，问题发生在绘制过滤，而非加载了另一张地图。修前已用真实Tk窗口复现4/10栋差异，独立评委另外检查了数据链。

|问题|修改位置|验收条件|验证证据|
|---|---|---|---|
|低建筑在主图消失|`ui.py:render_map`|全部10栋均显示；深色4栋需绕行，浅色6栋可飞越；ID及米制坐标与编辑器一致|真实Tk图元数量、颜色和逆变换坐标断言；主图/编辑器截图|
|建筑数与飞行障碍数混淆|`app.py:apply_result`、`map_hover`|分别显示建筑数及障碍数；可飞越建筑也能查看楼高及状态|实际主图元详情、94项测试与独立检查|
|导出仍缺建筑|`reporting.py:map_svg`|SVG保留所有建筑，包含编号、坐标、状态title和对应深浅颜色|真实结果导出XML解析；独立核验SVG几何|
|切换编辑器出现额外名称、人群区域及底图|`app.py:edit_map`、`map_editor.py:__init__/_build`|沿用主图名称、道路、人群区域开关；主简图重开不自动叠加底图；初次导入未定标/楼高未填的图片草稿保留底图|默认及反向开关的实际编辑按钮调用；原底图可手动开启；未定标schematic草稿检查|
|隐藏人群区域不便继续编辑|`map_editor.py:select/set_tool`|选择隐藏组件或启用对应绘制工具时显示相应图层；不改组件数据|实际Tk选择/绘制工具断言|
|修改应用、取消或高度变化可能造成不同步|既有数据链保持；新增GUI回归|取消保留数据/结果；无修改应用保留航路与指标；编辑应用同步位置/楼高；25/120米巡航均保留10栋；导入Excel、起飞点结果回放也用当前快照|`cases/verify_map_consistency_gui.py`九组检查|

`engine.py`、`flight_map.py`、`site_selection.py`、调度和统计算法未修改。建筑是否参与避障仍按原高度判定；显示低建筑不会增加规划障碍。

## 复现及证据

从项目根目录运行：

```powershell
python cases/verify_map_consistency_gui.py
python -m unittest discover -s tests
```

GUI脚本创建实际Tk窗口，调用真实编辑按钮、编辑器和后台计算；只自动化操作及对话框选择，不替换仿真数据或绘制控件。截图可选命令为`python cases/verify_map_consistency_gui.py --output results/map_consistency_20261019`，截图功能需要Pillow并使用Windows目标窗口句柄，避免把其他应用窗口截入证据。脚本的图片案例也需要可选Pillow依赖。

证据目录：`results/map_consistency_20261019/`。

- `verification.json`：九组实际Tk检查通过，回调错误列表为空。
- `main-all-buildings.png`、`editor-same-buildings.png`：最终窗口采集。
- `unittest.txt`：最终源码完整94项测试通过，耗时32.200秒。
- 独立验收另见`docs/参赛验收/地图一致性独立复审.md`。

两窗口承担不同操作：主图显示航路及任务动画；编辑器用于调整组件。人员暴露开启时，主图为连续热力分布，编辑器为可编辑的人群椭圆；编辑器选中组件可显示名称及控制点。这些叠加元素不等同于建筑/点位坐标变化。窗口尺寸和适应窗口缩放各自计算，不要求两个窗口像素完全一致。
